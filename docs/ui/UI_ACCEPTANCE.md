# UI_ACCEPTANCE — UI 驗收條件與 G2 自我審查

> 階段：G2 UI/UX Prototype（2026-11-15）。對應的原型是 [prototype/index.html](../../prototype/index.html)。
> 依據：[G1 Grill 文件](../grill/g1-grill-input.md) 第 8、9 節與 [DESIGN.md](../../DESIGN.md) §9.6。
> 狀態：**G3 APPROVED / FROZEN（2026-11-15，專題負責人裁決）。** 第 3 節的審查是製作者的自我審查，不是獨立審查；G3 的結論由專題負責人作出。
> G3 Audit 的問題清單與修改前後比較在 [G3_AUDIT_REPORT.md](G3_AUDIT_REPORT.md)。

## 1. 這份文件怎麼用

- 第 2 節是驗收條件。G3 用它審查原型；M3 的 Streamlit 介面完成後，用同一份條件再驗收一次。
- 第 3 節是 G2 的審查結果：每一條條件在原型上驗證了什麼、用什麼方式驗證。
- 第 4 節列出沒有驗證的項目。
- 第 5 節是需要專題負責人在 G3 親自確認的項目。
- 第 6 節記錄 UI 的工作量風險。

「原型／Streamlit」一欄標示條件適用的對象。標成「僅原型」的條件只和原型有關；標成「有差異」的條件，Streamlit 的做法見 [UI_DESIGN.md](UI_DESIGN.md) 第 8 節。

## 3. G2 的審查結果（UI Acceptance Review）

### 3.1 審查方式

- 在本機以 `python -m http.server` 提供原型，於 Chromium 核心的預覽瀏覽器開啟。
- 用腳本切換十四個情境、按「規劃」，再讀取畫面上的文字與元素狀態來比對條件。
- 版面在 299、375 與 1280 像素三種寬度下檢查。
- 對比值依 WCAG 的公式計算。
- 最後一次完整重跑是在 2026-11-15，原型的最後一次修改之後。

審查者和製作者是同一個（Claude）。這是自我審查，不能取代 G3 的人工審查。

## 4. 沒有驗證的項目

- **螢幕閱讀器。** 沒有用任何螢幕閱讀器測試。
- **完整的鍵盤操作。** G3 Audit 以實際按鍵走過表單、規劃與候選的選取，但沒有涵蓋每一種情境與每一個元件。
- **橫向畫面、文字放大、減少動態的系統設定、實體手機的觸控。** 都沒有測試。
- **人工的視覺審查。** G3 Audit 看過 1280 與 375 兩種寬度的截圖，但截圖是在預覽窗格內縮小檢視的；沒有人在正常尺寸的螢幕上看過整體的視覺效果。
- **其他瀏覽器。** 只在一個 Chromium 核心的瀏覽器測試。
- **Streamlit 的實際呈現。** 沒有建出 Streamlit 頁面；可實作性是依文件判斷的。
- **真實資料。** 原型的數值、判定與說明文字都是模擬的，和正式的 Planner、Validator 無關。

| --- | --- | --- |
| Streamlit 介面的估計（1–1.5 人日）可能不夠 | 原型顯示介面有 8 個畫面狀態；Trip Result 有 9 個區塊，Validation & Replanning 最多 8 個區塊。這些都是 G1 決議要求的內容，不是新增的 | 不調整 Must 範圍，也不調整 19–24 人日的總量。超出時依下方的順序簡化，並記錄實際人日 |
| 狀態的組合多 | 計畫狀態、搜尋狀態、說明來源與資料模式互相組合 | 測試以原型的十四個情境為準，不另外擴充 |
| 原型和 Streamlit 的外觀不同 | 字型、提示框顏色與表格樣式由 Streamlit 的主題決定 | 以內容與狀態為驗收對象，不追求外觀一致 |
| 手機上的資訊量偏多 | G3 Audit 的量測：375 像素時 Trip Result 有 3.4–3.7 個畫面，四張數值卡片直排，五個表格要橫向捲動 | G3 裁決：接受現狀（N1–N3）。手機上精簡表格欄位可以留給 Spec |
| Prototype 階段的人日（0.5–1） | 原型與三份文件在一個工作階段內完成，早於原定的 11/20–11/22。專題負責人的 G3 審查時間還沒計入 | G3 後記錄實際花費 |

時間不夠時的簡化順序（由先到後）。這是建議，需要專題負責人在 G3 決定：

1. 候選的選取改為只顯示唯讀表格，不切換逐條規則結果（條件 D5）。
2. 錯誤摘要省略，只保留欄位旁的錯誤（條件 B4 的摘要部分）。
3. 規劃進度改為單一的進行中提示（條件 B6 的步驟文字）。
4. 加油安排與天氣合併成一個表格。

不可簡化的項目：計畫狀態與搜尋狀態的標籤、逐條規則結果、UNKNOWN 的四項說明、待確認事項、來源證據、資料模式的標示、結果過期的提示、無可行解時「不是有效的建議」的標示。
