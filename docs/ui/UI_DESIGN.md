## 1. Design System 的來源

Design System 由 `ui-ux-pro-max` Skill 產生（查詢：分析型儀表板與決策輔助工具；變化度 2、動態 2、密度 7），再依本專題的限制取捨。

| Skill 的建議 | 處置 | 理由 |
| --- | --- | --- |
| 風格：Minimalism & Swiss Style | 採用 | 適合儀表板與專業工具；無障礙風險低 |
| 配色：藍色主色、淺色背景 | 採用 | 主色用在按鈕與分頁 |
| 強調色：琥珀色的行動按鈕 | 不採用 | 琥珀色保留給 CONDITIONAL，避免和狀態顏色混淆；行動按鈕用主色 |
| 內文文字用深藍 `#1E3A8A` | 部分採用 | 只用在標題；內文改用 `#0F172A`，對比更高 |
| 字型：Fira Code／Fira Sans（Google Fonts） | 不採用 | 介面是繁體中文；原型不載入外部資源，改用系統字型 |
| 版型：Enterprise Gateway（行銷首頁） | 不採用 | 這是工具頁面，不是行銷頁 |
| 動態：捲動進場動畫（GSAP） | 不採用 | Streamlit 做不出來，這個工具也不需要 |

另外查詢了三項 UX 準則並套用：不只用顏色傳達資訊、表單錯誤要有可聚焦的摘要並保留欄位旁的錯誤、長時間的操作要有進度回饋。

## 2. 設計原則

1. **狀態是主角。** 計畫狀態、逐條規則結果與來源證據都以獨立區塊呈現，不放在對話文字裡。
2. **顏色加文字。** 每個狀態標籤都有圖示、英文代碼與中文說明，不只靠顏色。
3. **不知道就說不知道。** UNKNOWN 用灰色，不借用紅色或綠色；一定附上原因與人工確認指引。
4. **模擬與真實分開。** 模擬資料、資料快照與真實 API 各有標籤；頁面頂端固定顯示資料模式。
5. **做得出來才畫。** 只使用 Streamlit 1.67.0 的標準元件能做到的互動。

## 4. 狀態的呈現

| 狀態 | 標籤文字 | 顏色 | Streamlit 的標籤顏色 |
| --- | --- | --- | --- |
| 計畫 FEASIBLE | FEASIBLE 可行 | 綠 | green |
| 計畫 CONDITIONAL | CONDITIONAL 有條件可行 | 黃 | yellow |
| 計畫 INFEASIBLE | INFEASIBLE 不可行 | 紅 | red |
| 規則 PASS | PASS 通過 | 綠 | green |
| 規則 FAIL | FAIL 未通過 | 紅 | red |
| 規則 UNKNOWN | UNKNOWN 無法判定 | 灰 | gray |
| 搜尋 COMPLETE | 搜尋完成 COMPLETE | 綠 | green |
| 搜尋 INCOMPLETE | 搜尋未完成 INCOMPLETE | 橘 | orange |
| 模擬資料 | 模擬 | 紫 | violet |
| 資料快照 | 資料快照 | 藍 | blue |
| 真實 API | 真實 API | 灰（G3 裁決 N5） | gray |

規則：

- CONDITIONAL 一律寫「有條件可行」，不單獨出現「可行」。
- 搜尋狀態和計畫狀態是兩個標籤，不合併。
- 保守估計不稱為 P90。降雨的分類稱為低／中降雨機率與高降雨機率提醒，不稱為警特報。
- 任何 INFEASIBLE 的候選都標明「這不是有效的建議」。
- 輸出驗證錯誤時不顯示計畫狀態標籤。
- 綠色只用在 PASS、FEASIBLE 與搜尋完成。來源類型不使用綠色；正式產品的 API 來源標籤使用中性的灰色，在正式介面實作時處理。
- 高降雨機率提醒維持琥珀色與文字警示（G3 裁決 N4）。
- 本地衍生資料（例如個人配速表）與本地設定檔（例如 Rider Profile）的來源類型由 Spec 定義，不得標成 API（G3 裁決 N6）。
- 原型的資料全部是模擬的，所以來源證據的每一列都標「模擬」，正式產品預計標示的類型寫成標籤旁的文字。模擬資料不得標成真實 API。
- 頁面頂端的 Snapshot Mode 標籤描述的是畫面上的結果，不是勾選框目前的狀態。還沒有結果時，它描述下一次規劃。
- 狀態標籤不換行。空間不夠時讓整組標籤換行，或讓表格在自己的容器內橫向捲動。

## 5. 版面

單頁，由上到下：

1. 頁首：產品名稱與資料模式的標籤。
2. Trip Planner：固定呈現的輸入區。
3. 規劃進度：只在規劃時出現的步驟文字。
4. 追問：只在需求有歧義時出現的對話訊息。
5. 結果過期的提示：輸入和上次規劃不同時出現。
6. 結果區：兩個分頁，Trip Result 與 Validation & Replanning。

內容寬度上限 1120 像素。段落、清單與說明文字的寬度上限是 46em（約 46 個全形字），和 Streamlit 置中版面的寬度相同。欄位以自動換行的格線排列；寬度在 375 像素時每列一欄，頁面沒有橫向捲動，表格在自己的容器內橫向捲動，表格的說明文字維持可見區域的寬度。

規劃完成後，規劃進度收合成一行，不佔用按鈕與結果之間的空間。

原型另外有一個虛線框的「Prototype 控制」區塊，用來切換模擬情境。它不屬於產品畫面，正式介面不會有。

| 出發油量 | `st.number_input`（0–100） | 必填；送出後程式再檢查一次 |
| 自然語言需求 | `st.text_area` | |
| Snapshot Mode | `st.checkbox` 或 `st.toggle` | |
| 規劃按鈕 | `st.button` | 唯一會觸發計算的操作；放在表單之外 |
| 欄位錯誤與錯誤摘要 | `st.error` | 見第 8 節的差異 |

## 7. 不使用的互動

- 只在滑鼠停留時才出現的資訊。
- 拖曳。
- 表格內直接編輯。
- 畫面自動更新或伺服器主動推送。
- 地圖互動。
- 巢狀的可展開區塊；超過一層的欄位巢狀。
- 表單內的一般按鈕或下載按鈕。
- 結果產生後的自由對話。

## 8. 原型和 Streamlit 的已知差異

| 項目 | 原型的做法 | Streamlit 的限制 | 正式介面的做法 |
| --- | --- | --- | --- |
| 錯誤摘要 | 摘要中的每一項可以點擊跳到欄位，送出失敗後焦點移到摘要 | 標準元件無法控制焦點，也沒有欄位錨點 | 顯示摘要與欄位旁的錯誤，不做跳轉與焦點移動 |
| 候選的選取 | 每列一個單選鈕；重新繪製後把焦點放回選取的那一列 | `st.dataframe` 的列選取是勾選欄，焦點由元件自行處理 | 使用單列選取模式 |
| 來源類型 | 標籤一律是「模擬」，旁邊以文字註明正式產品的類型 | 正式產品的資料有真實的類型 | 每一列直接顯示它的類型標籤 |
| 分頁切換 | 規劃完成後自動回到 Trip Result | 分頁不能用程式切換 | Trip Result 是第一個分頁，重新執行後預設顯示它 |
| 提示框的顏色 | 結果過期用橘色 | 內建的提示框顏色固定 | 使用 `st.warning` |
| 字型 | 系統字型 | 預設字型由主題決定 | 使用 Streamlit 的預設字型 |

這些差異不改變畫面要呈現的內容與狀態。
