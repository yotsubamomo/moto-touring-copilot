## 1. 問題

`http_transport.py:76` 依 CL-R1-25 第 2 項 (d) 呼叫 `ssl.create_default_context()`。它會讀 `SSLKEYLOGFILE`，有設定時把 TLS session keys 寫到該檔（P-1、P-2，Windows 亦然）。這與 CL-R1-25 第 2 項 (b)「不讀任何環境變數」的字面並存時語義不清。要裁決：(b) 是否涵蓋標準函式庫內部對 `SSLKEYLOGFILE` 的讀取；涵蓋時對 #16 的具體要求與 evidence；不涵蓋時的理由與 disposition。

## 2. 裁決（CL-R1-28）

### 2.1 第 2 項 (b) 的範圍

**第 2 項 (b) 不涵蓋標準函式庫與 OpenSSL 內部對環境變數的一切讀取；但 `SSLKEYLOGFILE` 造成的寫檔落在第 5 項「不寫檔、不保留請求或回應」之內，#16 必須消除它（第 3 節）。**

1. **(b) 的範圍。** (b) 的標題是「不使用代理」，所在的第 2 項是「端點不可被轉向（H-1）」；句子本身列舉的是代理與端點類變數，並以「都不改變連線的主機與埠」作結。它約束兩件事：(i) `http_transport.py` 自己的程式不讀任何環境變數（與第 5 項「原始碼不含 `environ`、`getenv`」一致，對全部變數，不只代理）；(ii) 任何環境變數，不論經由哪一層，都不得改變連線的主機、埠、代理或轉址。
2. **字面讀成「標準函式庫內部也不讀任何變數」無法滿足。** 第 1 項指定使用 `ssl`，而 `load_default_certs()` 在所有平台都讓 OpenSSL 參考 `SSL_CERT_FILE`、`SSL_CERT_DIR`（P-5）。要避開它，只能自己寫信任來源的載入（例如 Windows 專用的 `ssl.enum_certificates`）或改用第三方套件；前者容易載錯用途或漏掉憑證而降低驗證，後者違反第 1 項。一個不可滿足的讀法不是合理讀法（治理 §3.6-A）。
3. **`SSLKEYLOGFILE` 的實際後果由第 5 項處理。** 設定時，每一次路線、道路屬性與狀態請求的 TLS 秘密都被附加寫到一個檔案；有人另外截取到流量，就能解開請求內容（公開地標座標、通用 User-Agent）與回應。這是 `http_transport.py` 建立的 context 所做的寫檔，而且寫的是能還原請求的資料，與第 5 項「不寫檔，不保留請求或回應」直接牴觸。它可以用公開 API 以零成本避免，且不降低任何驗證（P-3、P-4）。所以本項不是「記為觀測」的類型。
4. **不構成 E-DA/D1。** 兩種處理（要求消除、記為觀測）的後果有差別，但現有證據可以裁決：P-2 證明它會寫檔，P-3、P-4 證明有不降低驗證的替代做法。也不是 E-DA/D2：本 DA 先前沒有對 `SSLKEYLOGFILE` 作過決定，C2R1-F3 指出的是 CL-R1-25 的遺漏，不是推翻。

### 2.2 更正 CL-R1-25 第 2 項 (d) 括號內的觀測

CL-R1-25 (d) 寫「在非 Windows 平台上，標準函式庫的預設信任來源可受 `SSL_CERT_FILE` 等環境變數影響……專案的執行平台是 Windows，本 record 不另列 tracked item」。**「非 Windows」不正確**：P-5 顯示 Windows 上 `load_default_certs()` 也呼叫 `set_default_verify_paths()`，`SSL_CERT_FILE`、`SSL_CERT_DIR` 在 Windows 上同樣可以**增加**信任的根憑證（不會移除系統存放區的憑證，也不關閉驗證）。

處置：

- 它不改變連線的主機與埠，不關閉主機名稱檢查或憑證驗證，所以不違反第 2 項 (b)、(d)。能設定這兩個變數的人也能設定 `PYTHONPATH` 等更直接的變數，不在本傳輸層要防的範圍（本傳輸層要防的是常見的開發環境設定意外轉向端點，例如代理變數）。
- 依第 2.1 節第 2 點，不要求避開它。
- 因為先前的觀測寫錯了平台，改列為 **tracked item TI-C2R1F3-1**（第 5 節），使 SPEC-R1 的 SIA 與之後的文件看得到這項已知限制。
- 另記：OpenSSL 可能在程式庫初始化時依 `OPENSSL_CONF` 載入設定檔；本 record **沒有驗證** Python 3.11.2 的 `_ssl` 是否如此（NOT VERIFIED），併入 TI-C2R1F3-1。

### 2.3 CL-R1-28 的條文

**CL-R1-28（CL-R1-25 第 2 項 (b)、(d)、第 5 項的 clarification）。**

1. **(b) 的範圍。** 「不讀任何環境變數」指 `http_transport.py` 自己的程式（第 5 項的靜態禁止照舊），以及「任何環境變數都不得經由任何一層改變主機、埠、代理或轉址」。標準函式庫與 OpenSSL 內部的其他讀取，由第 5 項（不寫檔、不保留請求或回應）與 (d)（不降低 TLS 驗證）約束。
2. **TLS context 的建立方式（取代 (d) 的「使用 `ssl.create_default_context()` 建立的 context」）。** 傳輸層以 `ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)` 建立 context，**明確**設定 `verify_mode = ssl.CERT_REQUIRED` 與 `check_hostname = True`，再呼叫 `load_default_certs(ssl.Purpose.SERVER_AUTH)`。不呼叫 `ssl.create_default_context()`（P-2：之後再把 `keylog_filename` 設為 `None` 仍會建立檔案）；不把 `keylog_filename` 設為任何路徑；不呼叫 `load_verify_locations`、`load_cert_chain`、`set_ciphers`，也不降低 `minimum_version`、`options`、`verify_flags`。其他 (d) 的要求不變：沒有關閉驗證或載入其他憑證的參數。
3. **不低於標準函式庫的預設。** 該 context 的 `check_hostname`、`verify_mode`、`verify_flags`、`options`、`minimum_version`、`maximum_version`、`protocol`、`hostname_checks_common_name`、`post_handshake_auth`、`security_level` 與 `cert_store_stats()`，必須與同一直譯器在沒有 `SSLKEYLOGFILE` 時 `ssl.create_default_context()` 的結果相等（以測試證明，第 3.2 節 T-11）。`requires-python` 是 `>=3.11`；若之後的 Python 版本在 `create_default_context()` 中加入更嚴的設定（例如 `verify_flags`），這個測試會失敗，修正方式是在傳輸層明確加上相同的設定，**不得**放寬測試。
4. **模組說明不得過度宣稱。** 說明不寫「沒有任何東西讀取環境變數」；改寫為：本模組不讀環境變數；context 以明確設定建立，因此不參考 `SSLKEYLOGFILE`；預設信任來源的載入（`load_default_certs`）讓 OpenSSL 參考 `SSL_CERT_FILE`、`SSL_CERT_DIR`，它們只能增加信任的根憑證，不改變主機與埠（CL-R1-28）。
5. **不改變的部分。** CL-R1-25 第 1 項、第 2 項 (a)、(c)、(e)、第 3、4、6 項；T-1～T-10；`valhalla.py`、`adoption.py`、`source.py`。
