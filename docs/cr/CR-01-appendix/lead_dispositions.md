# CR-01 審查後的處置（lead，2026-11-15）

> 對象：[review_1_post.md](review_1_post.md) 與 [review_2_post.md](review_2_post.md) 的發現。兩份審查的結論都是「修正後可以交給專題負責人批准」，沒有 Blocker。
> 原則：修正文件的不準確、不一致、過時與缺漏；不替專題負責人做決定。需要裁決的事項一律列入待裁決清單，附選項、lead 的建議與期限。

## 1. 共用名稱（各文件必須一致）

| 名稱 | 意義 |
| --- | --- |
| `trip_type` | `one_way` 或 `round_trip` |
| `route_source` | `trip`、`routing` 或 `target_gpx` |
| `snapshot_id` | 一條路線對應一個路線快照 |
| `legs[]`、`direction` | 快照中的路段方向：`outbound` 或 `return` |
| `has_highway` | 路線引擎回報的國道旗標，逐方向記錄 |
| `freeway_check` | 獨立的國道檢查結果（道路等級與道路名稱），逐方向記錄 |
| `endpoint_offset_m` | 要求的地標到折線端點的距離 |
| `ridden_share_pct` | 路線里程中以前騎過的比例 |
| 檢查點的 `kind` | 新增 `turnaround`（草稿，待 Ticket 實作） |

## 2. 直接修正（不需要裁決）

| 編號 | 處置 |
| --- | --- |
| L-1 | 契約的說法改為：契約 2 的欄位有變更；`route_id` 與 `checkpoint_id` 的格式放寬，會連帶影響契約 1 與契約 4 中引用這兩個 ID 的格式檢查；契約 1、3、4 的欄位與不變條件不變 |
| L-2 | 契約 2 加入路線層級的 `trip_type`，檢查點的 `kind` 加入 `turnaround`（草稿） |
| L-3 | 來回行程是一個路線快照、兩個方向：去程與回程各送一次請求，**不反轉去程的折線**。每個方向記錄請求、折線、警告、國道旗標、獨立的國道檢查結果、端點偏移與取得時間；快照另記引擎版本與圖資日期；高度為選填。去回里程差超過 2% 時在路線摘要標示。描述引擎結果時，「去回同路」改為「同一組起訖與途經點的去程與回程」 |
| L-4 | 路線快照與路線摘要的欄位定義由 SPEC-001 負責；DESIGN §5 只寫摘要並指向 SPEC。預設休息與 `ridden_share_pct` 的算法也各指定一份文件負責，不互相推給對方 |
| L-5 | 路線的採用條件：獨立的國道檢查通過才採用，這一條沒有例外。「排除被忽略」的警告怎麼處理，取決於路線參數的裁決：採 `use_highways: 0` 時不送出排除，出現任何警告就拒收；選項「繼續用 `exclude_highways`」和拒收規則互斥，選它就要改寫這條規則。文件要寫明這個關係 |
| L-6 | G1 沒有重開的決議維持有效：保留全部評估過的候選（Q14）、UNKNOWN 的四項（Q25）、每一輪的結構化變更摘要（Q29）、規則 5 的內部紀錄（Q30）。SPEC 不得把它們標為延後；DESIGN §8 與 SPEC 要一致。G1 沒有要求、由 SPEC 自己新增的欄位（原因代碼、期限依據等）可以標為「提議延後，待專題負責人確認」 |
| L-7 | 行程清單是 `trip_id` 的唯一來源：新上傳的檔案以內容去重複後接續編號，已指定的 `trip_id` 不變動；實驗腳本一律讀清單，不自行編號 |
| L-8 | 對 LLM API 的隱私規則：送給 LLM 的只有騎士自己輸入的行程文字、結構化的條件，以及不含座標與軌跡點的工具輸出（含計畫路線的道路名稱）。不送原始 GPX、逐趟的騎乘資料與住家位置 |
| L-9 | 如實記錄：C2 已經在 16 趟配速行程上做過留一趟的比較，所以 E1 在配速行程上的數字不是事前預測；只有保留行程的評估是第一次看 |
| L-10 | 「整趟」的定義：一個 GPX 檔裁切後的範圍，也就是騎士記錄的一段行程。多數檔案是單向的一段，不是從家裡出發再回到家的一天 |
| L-11 | E1 的分析計畫（指標、分層、baseline、餘裕係數怎麼定）要在讀取任何保留行程的時間之前寫定並記錄日期 |
| L-12 | 研究問題 1 中的路線引擎 ETA：在沒有自架的情況下，只能在兩個公開地標之間的路段取得；取不到時如實報告為未比較 |
| L-13 | E2 題目的最小格式：每題是一個對應凍結快照的路線代號加上條件。A1 只收到文字描述的行程與條件，沒有工具；任何一組都不會收到座標或私有幾何。真實行程題最多 4 題（保留行程的趟數），可能沒有來回行程。預期狀態取決於來回行程規則 3 的題目，要等 D3 定案才能凍結 |
| L-14 | 現在就記錄 CR-01 對 A3 整體流程的改動：規劃之前先做路線解析、候選全數評估不分批、說明以固定模板優先。A2 與 A3 仍共用相同的路線快照、候選集合、工具與資料快照 |
| L-15 | E2 的凍結清單加入配速表版本、分級門檻與餘裕係數 |
| L-16 | 里程碑加入 E2 的準備工作：題庫、Oracle 腳本、Runner、A1／A2 的執行方式與 Pilot，排在 11/21–12/4 |
| L-17 | 新增一份「CR-01 之後和 Proposal 仍有的差異」清單；文件開頭不再只指向已過時的 §13.1 |
| L-18 | Minor 的發現：能直接修正的就修正 |
