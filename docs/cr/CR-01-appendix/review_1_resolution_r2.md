## 1. 結論

**PASS WITH ISSUES：沒有 Blocker，8 項 Major，7 項 Minor。** 三項裁決在處置 5.1／5.4／5.5、DESIGN §6.3、SPEC-001 7.9、SPEC-RESOLUTION-001 3.4／3.5 與 CR-01 第 20 節的寫法一致，沒有互相矛盾；Over-refusal Rate 的定義確實沒有動；狀態用語都照實（C3 是 BLOCKED／NOT RUN，SPEC-001 是未凍結的 Draft v0.2，只有 SB-2 與 SB-9 是 CLOSED，E2 未執行）。問題在於幾個定義還不能照著實作：(1) 時間相依的 Oracle 要讀「題目的出發時間」，但題目沒有這個欄位，出發時間是各組的輸出；(2) 必備的「只有去程有提醒」這一題，在去回同路的路線上做不成時間不變題；(3) Oracle 用的「路段對應鄉鎮」從哪裡來、人工核對什麼，都沒有寫，禁止匯入的清單也沒有 `routes`；(4) 時間相依的 Oracle 和 production 共用配速表數值、路段類別與同一份算式的讀法，文件沒有把這些寫成「共用輸入」，也沒有界定實作之後可以宣稱什麼；(5)「不以規則 1–5 評分」這一條沒有為規則 3 寫例外；(6) H2 只由主要結果表判定、另外兩張表不能改變結論，這句話沒有寫；(7)「出題但不計分」的題目算不算在 `N_total` 內沒有定義；(8) 敏感度分析的兩個數沒有分母，而且在模擬預報題上是出題時就決定的。這些都屬於 E2 的規格，不擋 SPEC-001 的凍結，但要在 12/5 題庫凍結之前（最好在 M2 的 Oracle 規格初版）改完。

## 3. 檢查過、沒有發現問題的部分

- 時間不變題與跨時段題的定義，在處置 5.1、DESIGN L729、SPEC-001 7.9、SPEC-RESOLUTION-001 3.4 四處逐字一致。定義本身對通過規則 1 的候選是成立的：範圍內每個鄉鎮在 [最早可出發時間, 期限] 內的各預報時段分類相同時，任何抵達時段取到的分類都相同；跨鄉鎮取最高值、FAIL 優先於 UNKNOWN、涵蓋區間邊界落在範圍內時歸為跨時段題，都和 SPEC-001 7.13 一致。
- 「沒有實作時間相依的 Oracle 時不得宣稱已驗證跨預報時段的正確對齊」在處置 5.1、DESIGN L732、L748、SPEC-001 7.9、SPEC-RESOLUTION-001 3.4、CR-01 第 20 節都有。「時間相依的 Oracle 是否實作尚未決定」照實寫出（L736、L779、處置 5.7）。
- 時間相依的 Oracle 不匯入 `pace`、Validator、Planner「或任何 production 的程式」，四處一致。
