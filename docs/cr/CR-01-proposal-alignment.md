## 1. 結論

1. **目標確實偏離了，偏離的地方是「路線怎麼來」與「來回」。** Proposal 的問題定義與範例是「起點、路線或途經點 → 實際道路 → 當天來回、天黑前回到家」（§1.3 p.6、§4.1 p.24、§4.8 p.32、§4.9 p.33）。現行 MVP 是兩條約 47 公里的固定單向路段。Agent 數量與分位數模型的縮減不是問題所在。
2. **現有成果大部分可以沿用。** 配速表依曲率分類，和道路無關；`build_route` 接受任何路徑（`research` 以公開地標實測、`review_2` 讀碼確認）。資料契約只需要改契約 2 的兩處。
3. **建議的 MVP 做得到情境 A、D，以及縮小版的 B、C、E。** 剩餘工作量約 22.5–31.5 人日當量，到 12/20 沒有緩衝。它成立的前提是第 8 節的四項檢查在 11/20 前通過。
4. **有兩個風險會直接影響結果的可信度，都還沒有用資料驗證：** 路線引擎的幾何算出的曲率可能比 GPS 軌跡「直」，讓 ETA 偏樂觀；來回行程的平面轉場段時間可能偏樂觀。兩者都排在最前面檢查。

## 3. 建議的 User Journey

1. **建立或更新 Profile。** 匯入歷史 GPX（可多檔，可之後再加）→ 清理、切段、分類 → 重建配速表 → 涵蓋度報告：可用的行程數、各類別的路段數、累計公里。
2. **描述行程。** 一個文字欄（例如「從某地出發走某條公路來回」），加上日期、最早出發、最晚回到出發點、出發油量。可以改為提供目標路線的 GPX。
3. **補齊條件。** Planner 把文字轉成結構化的路線請求。缺起點、不知道從哪一端進、沒說來回或單向時追問。
4. **取得路線。** 公路與地標由人工整理的詞彙表對到錨點 → 路線引擎算出實際道路 → 存成快照 → 檢查不含國道 → 顯示里程與主要道路名稱，作為採用的條件。
5. **切段與檢查點。** 路線切段並分類 → 沿線加油站與折返點成為檢查點 → 算出這條路騎過多少。
6. **規劃與驗證。** 候選出發時間 → 個人 ETA（典型與保守，含休息）→ 日照、天氣、加油站、路況工具 → Validator 判定規則 1–4 → 選出最晚的可行出發時間。全部不可行時 Planner 調整休息與加油後重試。
7. **輸出。** 計畫狀態、建議出發時間、回到出發點的時間、加油安排、天氣、來源證據、待確認事項，以及「這條路你騎過多少、估計依據是什麼」的說明。
8. **無可行解。** 說明原因與替代方案。修改條件後重新規劃。

## 8. 對 E1／E2、期末展示與時程的影響

**E1。** 評估單位由示範路段改為整趟。主假設仍在山路段；整趟與轉場段的誤差用來判斷規則 1 可不可信。另外依「騎過多少」分成熟悉與不熟悉兩層報告。餘裕係數由留一趟的殘差決定，仍然不稱 P90。

**E2。** 三組不變。題目帶路線代號並對應凍結的快照，自然語言轉路線的能力放在 Demo 與少量不計分的案例。E2 驗證的仍是一組凍結路線，任意路線的能力不在 E2 的結論內。真實行程題的路線幾何不能進版控（會暴露住家附近的範圍），只放雜湊與摘要，或裁成兩個公開地標之間的山路段。

**先前的裁決需要重新處理。** M1 Review 否決了平直高速的第三條路線、排除了一趟保留行程，並留下一項尚未執行的「高速直路是否屬於適用範圍」檢查。整趟評估會把這些路段帶回來。保留行程的指定規則也要改；改之前要先記入 Change Log，而且不得先讀保留行程的時間。

**期末展示。** Demo 只讀快照，不依賴現場的網路。可以展示一條來回行程從描述到驗證的完整流程。

**工作量。** `research` 估 24.5–31.5（它的表格實際加總是 23.5–33）；`review_2` 砍掉三項新增設計後估 21–29；加上 `review_1` 建議的幾個小項（我粗估 1.5–2.5，這個數字沒有經過審查），約 **22.5–31.5 人日當量**。舊計畫剩餘的是 15.5–19。到 12/20 有 35 個日曆天，沒有緩衝。前兩天的產出速度說明程式與文件不是瓶頸；瓶頸是金鑰、真實資料、LLM 的實際執行、你的審查與期末交付，這些都還沒有實測速度可以依靠。

**關鍵路徑。** 路線來源與快照 → 路線建立與檢查點 → 資料工具 → Validator → Planner → 介面 → E2 凍結與執行 → 期末交付。E1 可以平行。

## 13. 保留行程的選取規則（2026-11-15 凍結，早於任何資料分析）

1. **可選的行程**：匯入清單中 `inventory_status` 為 `included` 的行程。2026-11-14 被排除的那一趟維持排除，等專題負責人重新裁決；它不進配速表，也不當保留行程。
2. **保留行程**：依 GPX 第一個軌跡點的時間排序，取最新的 K 趟。K＝max（3, 可選行程數的 20% 無條件進位）。時間相同時依 `trip_id` 排序。
3. **只用 metadata**：選取只讀每個檔案的起始時間，不讀軌跡、速度或任何由騎乘時間導出的量。
4. **舊的指定作廢**：先前依示範路線指定的兩趟保留行程（它們的時間從未被讀取）改依本規則重新歸類。
5. **已知的污染**：新指定的保留行程中，凡是在 M1 Spike 中當過配速行程的，它們的時間已經被用來取分級門檻與建 Spike 版的配速表。處理方式：分級門檻、配速表與餘裕係數全部只用新的配速行程重建；Spike 的數字不作為結果報告。這一點在期末報告的限制中說明。
6. **凍結之後**：正式 E1 之前不得讀取保留行程的時間。不得以保留行程調整模型、類別、餘裕係數或風險門檻。之後新匯入的 GPX 一律歸為配速行程，除非另立一次有紀錄的重新指定。
7. **紀錄**：指定結果寫入版控外的私有清單；公開文件只記錄趟數與清單的雜湊。

**C2 的發現**

- 低曲率路段的預測偏樂觀（平均 −16.2%）；中高曲率路段沒有系統性偏差（−0.3%）。只依曲率分類時，直路類別混了不同性質的道路。
- 把短停留（每次不到 3 分鐘）算進實際時間後，整趟誤差是 −19.1%，幾乎每一趟都偏樂觀。短停留相當於移動時間的 17.0%。現行 ETA 只算移動時間，所以抵達時間會比估計晚約兩成。這直接影響規則 1。
- 約 2,230 個一秒鐘的「停留」是位置重複造成的假象，`ingest` 把它們算成停留，使移動時間少算約 3%。
- 留一趟的 16 次出現 12 組不同的分級門檻，門檻不穩定。

依第 8 節事前寫定的處理：C2 未通過時，加上停等寬放，或把誤差的宣稱限縮到山路段並寫入限制。**停等寬放是否由 Should 升為 Must，等專題負責人裁決**（2026-11-15 審查處置 P-2：升為 Must，見第 18 節）；在裁決之前，設計文件把它記為待決。

**私有資料盤點（彙總）**

- 裁切後 1,358 公里，每趟中位數 77 公里；可用路段 1,157 段。三個類別各約 385 段、來自至少 14 趟，都達到 30 段與 3 趟。
- 起點與終點相近的完整來回不到 3 趟；至少 14 趟是單向的一段。把同一天的行程串起來，完整來回的日子也不到 3 天。
- 門檻是三分位數，所以低曲率占 33.4% 的里程只是定義的結果，不能說明轉場占多少。

對計畫的影響：E2 的真實行程題多數會是單向的山路段，「回到出發點的時間誤差」只能在極少數樣本上報告；轉場里程的比例無法從現有資料得知。

**保留行程的限制（必須寫入期末報告）。** 新指定的 4 趟保留行程在 M1 Spike 中都當過配速行程：它們的時間曾被用來取分級門檻與建立 Spike 版的配速表，也出現在 M1 Review 的方法探索中。因此它們不是完全沒被看過的資料。處理方式：門檻、配速表與餘裕係數全部只用 16 趟配速行程重建；Spike 的數字不作為結果；從凍結起，不得以保留行程調整模型、類別、餘裕係數、規則或風險門檻。
