## 目的

在整合後端之前，用模擬資料把 CR-01 新增與改動的畫面做成可以實際操作的 Streamlit 骨架，讓專題負責人驗收畫面與操作流程。它是 CR-01 的 UI Delta Prototype；`prototype/index.html` 保留為 G3 Frozen Baseline，不修改，也不另外製作第二份 HTML。

## 規格依據

- `docs/ui/UI_CR01_DELTA.md`（介面差異、驗收條件第 11 節、元件對應第 12 節）。
- `docs/cr/CR-01-appendix/ui0_decision_table.md`（22 項已確認的固定文字與操作流程）。
- `docs/spec/SPEC-001-plan-schema.md` 第 5.5 節（固定文字）、第 7.12 節（輸入保護的驗收案例）、第 4.1 與 4.2 節（休息需求、追問）。
- G3 凍結的 `docs/ui/UI_DESIGN.md`、`UI_FLOW.md`、`UI_ACCEPTANCE.md`：沒有變更的部分沿用。
- Streamlit 1.67.0，只用標準元件。

## 範圍

| 編號 | 畫面 | 要做出來的內容 |
| --- | --- | --- |
| 1 | Profile 區 | 歷史 GPX 的多檔選取與「更新 Profile」按鈕；涵蓋度摘要（三個數值與各類別的資料量）；三種資料量的白話說明；處理結果；隱私說明 |
| 2 | Trip Planner：行程描述與追問 | 行程描述欄與欄位下方的說明；輸入保護命中時的訊息；一輪追問：缺起點、進入端、行程型態、休息對應不到地點、休息的方向（行程型態與方向在同一輪）；追問之後仍對應不到時的表單訊息 |
| 3 | Trip Planner：行程型態與期限 | 來回／單向的切換；期限的名稱隨行程型態改變；出發錨點的說明句 |
| 4 | 路線確認 | 行程型態、里程、主要道路名稱、路線來源與標籤；兩種路權提醒；去回里程差的提示；配速資料中的路線涵蓋比例（三種情形） |
| 5 | 錯誤與 UNKNOWN | 六種路線錯誤（七則文字）；評估失敗；UNKNOWN 的呈現（沿用 G3 凍結的做法） |
| 6 | 天氣與休息 | 天氣表的去程與回程分列，回程標示為規則 3 的範圍；去程有高降雨機率提醒時的句子；預報時段的說明；休息的來源（騎士指定或預設）；「採用的條件」中的休息策略；抵達時間旁的說明；預設餘裕係數的說明 |

以模擬資料的情境切換呈現各種狀態（做法沿用原型的情境選單），每個情境都標示為模擬。

## 只用模擬資料

- 不讀取、不解析任何 GPX；上傳元件只用來驗證操作，選取的檔案內容不使用。
- 不呼叫路線引擎、語言模型或任何真實的 API；不讀取 `data/`。
- 畫面上的數值、道路名稱與預報都是寫在程式裡的模擬資料，並標示為模擬。
- 輸入保護可以用簡化的比對來示範訊息；確切的正規表示式屬於之後的實作 Ticket。

## 驗收條件

| 編號 | 條件 |
| --- | --- |
| UI0-1 | 範圍表的六個畫面都可以在瀏覽器中操作，每個狀態都有對應的模擬情境 |
| UI0-2 | UI_CR01_DELTA 第 12 節列出的元件在 Streamlit 1.67.0 都可以使用；做不到的逐項列出，並說明替代的做法 |
| UI0-3 | 固定文字和 SPEC-001 第 5.5 節與決策對照表的裁決逐字相同 |
| UI0-4 | 追問只有一輪；行程型態與休息方向出現在同一輪；方向的問題只在來回行程才需要回答 |
| UI0-5 | 期限的名稱隨行程型態切換；切換時已填的值是否保留，照實記錄（決策對照表 U-9 的退路） |
| UI0-6 | 375 像素寬度沒有整頁的水平溢出 |
| UI0-7 | 所有操作都可以只用鍵盤完成 |
| UI0-8 | UI_CR01_DELTA 第 11.1 節的驗收條件中，可以用模擬資料檢查的都逐條記錄結果；需要後端才能檢查的列為「整合後驗收」 |
| UI0-9 | 畫面上沒有任何真實的行程資料、座標、日期時間或私有的路線名稱 |
| UI0-10 | 交付一份簡短的紀錄：每個驗收條件的結果、元件的限制、和 UI_CR01_DELTA 不一致的地方 |

完成後由專題負責人實際檢視，進行一次 UI Delta Review（暫定 11/28）。**通過之後才開始正式的介面與後端整合。**
